# folio의 제품·데이터 판단

이 문서는 구현 목록보다 **왜 그 방식을 골랐는지**를 남깁니다. 아래의 선택은 개발 중의 판단이며, 실제 이용자 평가로 확정한 결론은 아닙니다.

| 판단할 문제 | 선택한 방향 | 이유와 감수한 한계 |
| --- | --- | --- |
| 첫 화면을 무엇으로 채울까? | 표지와 한 줄 소개가 있는 책 가판대를 먼저 보여준다. | 취향 입력을 끝내기 전에도 책을 둘러볼 수 있게 했다. 첫 네 권은 편집 예시이며 실시간 신간으로 부르지 않는다. |
| 무엇이 개인화의 근거가 될까? | ‘좋아한 책 + 좋았던 이유’를 한 쌍으로 기록한다. | 기분만 고르는 입력보다 실제 독서 경험을 다음 선택에 연결한다. 책 소개에 같은 단서가 없으면 취향 일치로 표시하지 않는다. |
| 추천 후보를 몇 권 보여줄까? | 근거가 있는 책만 최대 세 권 보여준다. 0권도 허용한다. | 제목의 단어·쪽수만으로 ‘실무에 도움’이나 ‘가볍게 읽힘’을 주장하지 않기 위해서다. 빈 결과가 늘어나는 단점은 재탐색 안내로 보완한다. [평가 사례](../eval/recommendation-eval-2026-10-06-v03.md) |
| 국내 책의 검색 범위를 어떻게 넓힐까? | 알라딘 공개 주간 목록, 도서관 정보나루, Google Books, Open Library를 구분해 함께 사용한다. | 한 자료원에는 소개·표지·최근 출간 정보가 빠질 수 있다. 판매 순위는 출간일과 다른 정보이므로 섞어 표시하지 않는다. 자료원 응답이 바뀌면 결과도 달라진다. |
| AI가 만든 이유를 어디까지 믿을까? | 실제로 검색된 후보의 ID와 소개 인용문을 서버에서 다시 대조한다. | AI가 원문에 없는 문장을 만들어도 사용자에게 근거처럼 보이지 않도록 한다. 원문 표현의 존재는 독자 만족도를 증명하지 않는다. |
| 책장이 커지면 어떻게 할까? | 한 쪽에 12권을 보여주고 다음 쪽으로 넘긴다. | 네 권 정도만 보이는 장식용 책장보다 실제 독서 기록에 쓸 수 있게 했다. 13권 시험은 통과했지만 대량 저장 속도는 아직 평가하지 않았다. |
| 잡지 소품을 자동으로 새 상품처럼 보일까? | 출처와 확인일이 있는 편집 목록으로 운영한다. | 소품은 잡지를 고르는 진입점이지만, 공개된 상품 페이지에는 실시간 재고·가격 보장이 없다. 새 호 확인을 매월 진행하도록 설정했으며 첫 실행은 아직 확인 전이다. |
| 계정 데이터를 어디에 둘까? | 다른 실습 서비스와 분리된 folio 전용 프로젝트를 사용한다. | 책장·메모의 접근 권한을 folio 단위로 관리하기 위해서다. 한 계정의 로그인과 불러오기는 확인했지만 다른 기기·두 계정 분리는 별도로 확인해야 한다. |

## 참고 앱에서 가져온 것과 두지 않은 것

- [Goodreads](https://www.goodreads.com/about/us)의 읽기 상태별 책장과 [StoryGraph](https://thestorygraph.com/)의 분위기·다음 책 정리를 참고했다. Goodreads는 **기능 비교 대상**이며 책 데이터 공급원으로 사용하지 않는다.
- [Pinterest 보드](https://help.pinterest.com/en/article/boards)처럼 책과 소품을 이름 붙인 보드에 담을 수 있게 했다.
- 독서 시간 측정, 소셜 모임, 실시간 상품 판매는 이번 핵심 흐름인 **기록에서 다음 책 선택까지**에 우선하지 않았다.
