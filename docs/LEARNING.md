# 수업에서 배운 내용의 적용

수업에서 배운 방법을 하나의 웹제품 흐름에 연결했습니다. 적용했다는 말만 적지 않고, **사용한 부분과 확인 가능한 결과**를 함께 남깁니다.

| 수업 주제 | folio에서 한 일 | 확인할 곳 |
| --- | --- | --- |
| 복잡한 업무를 여러 Agent에게 위임하기 | 국내 도서 자료원 조사, 추천 근거 평가, 기능 점검을 나눠 진행했다. 각 결과를 합칠 때 출처·기능 상태·검증 범위를 다시 구분했다. | [데이터 판단](DECISIONS.md), [추천 평가](../eval/recommendation-eval-2026-10-06-v03.md) |
| Harness와 평가(Eval) | 여섯 가지 읽기 조건으로 후보와 책 소개의 근거를 점검했다. 근거 부족을 성공으로 세지 않고 상단을 비웠다. 서버 자동 시험에는 외부 서비스 오류·키 누락·인용 불일치도 포함했다. | [평가 기록](../eval/recommendation-eval-2026-10-06-v03.md), `server.test.cjs`, `lib/*.test.cjs` |
| Agent 활용해 데이터 분석하기 | 검색 자료원의 제목·저자·표지·소개·출간일을 정리하고 누락을 살폈다. 판매 순위와 출간일을 다른 값으로 표시했다. | `server.cjs`, `lib/data4library.cjs`, [데이터 판단](DECISIONS.md) |
| 사주 서비스 만들기 | AI가 사람을 단정하기보다 근거를 보여주고 자기이해를 돕는 방식을 독서에 옮겼다. 좋아한 책과 이유를 취향의 단서로 쓰되, 몇 권으로 성격을 판정하지 않는다. | `dist/taste.js`, `dist/app.js` |
| 반복되는 Workflow 자동화하기 | 확인일이 있는 잡지 소품 목록에 새 호를 매월 점검하는 작업을 설정했다. 목록 파일과 공개 화면의 갱신은 별개이며 첫 월간 실행은 아직 확인 전이다. | `dist/curiosities.json`, [검증 기록](VALIDATION.md) |

## 직접 내린 판단

AI가 제안한 기능을 모두 넣기보다 사용자에게 필요한 흐름을 우선했습니다. **추천 이유가 검증되지 않으면 표시하지 않기**, **책장을 장식보다 기록에 쓰기**, **소품 데이터를 실시간 상품처럼 주장하지 않기**가 대표적인 선택입니다. 이 선택의 장단점은 [제품·데이터 판단](DECISIONS.md)에 따로 적었습니다.

배운 내용을 적용한 흔적과 완성도를 혼동하지 않습니다. 자동 시험이 통과해도 실제 독자가 추천을 유용하게 여기는지는 별도의 사용자 평가가 필요합니다.
