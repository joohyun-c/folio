# folio — 읽는 책이 쌓일수록 선명해지는 취향

**folio**는 여러 권을 동시에 읽는 사람을 위한 독서 기록과 책 발견 웹페이지입니다. 읽고 싶은 책, 읽는 중인 책, 다 읽은 책을 한 서가에 모으고, 좋아했던 이유를 바탕으로 다음 책을 고릅니다.

## 왜 만들었나요?

병렬독서를 하다 보면 책은 쌓이는데 지금 무엇을 읽는지, 어떤 책을 끝냈는지, 왜 좋았는지를 한눈에 보기 어렵습니다. 책을 찾을 때마다 처음부터 검색하는 대신, **내가 읽고 고른 기록이 다음 선택에 도움이 되면 좋겠다**는 생각에서 시작했습니다.

수업의 사주 서비스 실습에서 AI로 자기 이해를 돕는 화면을 만들며, AI가 사람을 단정하기보다 근거를 보여주고 스스로 돌아볼 계기를 주는 방식에 관심을 갖게 됐습니다. folio에서는 독서 기록과 취향의 이유를 그 단서로 사용합니다. 책 몇 권으로 성격을 판정하지 않고, “나는 어떤 책을 왜 좋아했을까?”를 살펴보도록 돕습니다.

핵심 흐름은 **기록 → 취향의 단서 발견 → 이유가 보이는 다음 책 선택 → 다시 기록**입니다. 잡지 부록 소품을 둘러보는 기능은 이 흐름에 더한 작은 발견의 재미입니다.

## 어떻게 사용하나요?

1. **내 책장**에 읽고 싶은 책과 지금 읽는 책을 담습니다. 동시에 여러 권을 ‘읽는 중’에 둘 수 있습니다.
2. 다 읽은 책을 표시하고 메모를 남깁니다. 서가에서 완독 날짜, 최근 기록, 많이 읽은 주제를 돌아봅니다.
3. 좋아한 책과 **좋았던 이유**를 적습니다. 예를 들어 문장, 인물과 관계, 새로운 지식, 실천할 방법 중에서 고를 수 있습니다.
4. 관심 주제·읽는 목적·분량을 선택해 후보를 비교합니다. 책 소개에서 근거가 확인되는 후보만 최대 세 권 제시하고, 고른 책을 바로 ‘읽는 중’으로 옮깁니다.

이 과정은 독서 취향을 확정하는 검사가 아닙니다. 기록이 쌓이며 다음 선택에 쓸 수 있는 단서를 발견하는 경험입니다.

## 지금 구현된 경험

| 경험 | 현재 동작 |
| --- | --- |
| 자라는 서가 | 책이 늘수록 서가의 단도 늘어납니다. 한 서가에 최대 12권을 보여주고 그 이후는 다음 서가로 넘깁니다. 전체·완독·읽는 중·읽고 싶어요를 골라 볼 수 있습니다. |
| 읽은 기록 | 완독 날짜와 메모, 가장 많이 읽은 주제를 보여줍니다. 최근 완독 네 권에서 전체 완독 목록으로 이동할 수 있습니다. 다 읽은 책의 주제에 따라 서재 분위기도 바뀝니다. |
| 다음 독서 결정 | 읽고 싶은 책 중 최대 세 권의 순서를 정하고, 분량과 메모를 비교해 ‘읽는 중’으로 옮길 수 있습니다. |
| 취향을 반영한 발견 | 좋아한 책 한 권과 좋았던 이유를 저장하고, 맞지 않았던 책 한 권도 선택적으로 적습니다. 다른 책의 실제 소개나 확인된 분량에 같은 단서가 있을 때만 추천 순서에 반영합니다. |
| 근거가 있는 추천 | 관심 주제·읽는 목적·분량으로 후보를 좁힙니다. Gemini가 한국어 추천 이유를 작성할 때에는 검색된 책과 실제 소개를 전달하고, 소개에 없는 인용문은 표시하지 않습니다. 근거가 부족하면 세 권을 억지로 채우지 않습니다. |
| 책 탐색 | 알라딘 주간 베스트셀러, 도서관 정보나루, Google Books, Open Library를 함께 활용합니다. ‘이번 주 베스트’와 ‘최근 2년 출간’은 다른 기준으로 보여줍니다. 자료 연결이 실패하면 예시 책과 출처를 구분해 표시합니다. |
| 책 옆의 발견 | 사진과 출처를 확인한 잡지 부록 소품 18개를 둘러보고, 검색·분류·정렬·저장할 수 있습니다. 목록은 편집 자료이며 실시간 재고나 가격 정보는 아닙니다. |
| 계정 | Google 로그인과 계정별 책장 저장을 연결했습니다. 로그인 전 기록은 현재 브라우저에 남습니다. 다른 기기에서의 복원은 추가 검증이 필요합니다. |

## 수업에서 배운 것의 적용

- **여러 작업의 위임:** 자료원 조사, 기능 점검, 추천 기준 검증을 나누어 개발했습니다.
- **데이터 분석:** 책의 출처, 판매 순위, 출간일, 소개 유무와 독서 기록을 구분해 사용합니다. 판매 순위를 신간 순서로 오해하지 않도록 표시합니다.
- **AI 연결:** Gemini를 서버에서 호출하며 외부 서비스에 접속할 때 쓰는 인증값은 화면 코드와 분리합니다.
- **평가와 검증:** AI가 후보에 없는 책을 만들거나 원문에 없는 구절을 추천 근거로 쓰면 결과를 제외합니다. [추천 이유 평가 기록](eval/recommendation-eval-2026-10-06-v03.md)에 실패 사례도 남겼습니다.
- **반복 업무:** 잡지 부록 목록의 확인일을 표시하고 새 호를 주기적으로 점검합니다. 웹페이지가 새 상품을 자동 수집하는 기능은 아직 없습니다.

## 확인한 결과와 남은 일

- 2026-10-07 기준 자동 검사 **26개**가 통과했습니다. 별도 시험 화면에서 책 13권을 담아 첫 서가 12권과 다음 서가 1권, 완독 필터·날짜·주제 요약·새로고침 뒤 유지를 확인했습니다. 너비 390px 화면에서도 서가가 가로로 넘치지 않았습니다.
- 실제 도서관 정보나루 검색 응답, Google Books 한국어 책, 알라딘 주간 순위와 Gemini의 한국어 추천 이유를 각각 확인했습니다. 모든 검색어에서 좋은 후보가 나오는 것은 아닙니다.
- 현재 좋아한 책과 이유는 **한 쌍**만 저장합니다. 여러 완독 책을 종합한 취향 변화 분석, 실제 이용자가 추천 이유를 납득하는지에 대한 평가, 다른 기기의 계정 복원은 다음 과제입니다.
- 읽은 쪽수나 독서 시간은 기록하지 않습니다. 완독 날짜는 ‘다 읽었어요’로 표시한 시점부터 남습니다.

## 로컬에서 실행하기

이 저장소는 아직 공개 웹주소로 배포하지 않았습니다. Node.js가 설치된 컴퓨터에서 이 폴더의 서버를 실행하면 브라우저에서 열 수 있습니다. 외부 데이터 연결에 필요한 **API 키**는 서비스에 제시하는 비밀 인증값이므로 GitHub에 올리지 않습니다. 다른 컴퓨터에서는 [설정 예시](.env.example)를 참고해 비공개 `.env` 파일을 별도로 준비해야 합니다. 기존 `.env`가 있으면 덮어쓰지 않습니다.

```powershell
node --env-file=.env server.cjs
```

`.env.example`의 `PORT=8768`을 사용했다면 `http://localhost:8768/`을 엽니다. `.env` 없이 실행할 때에는 사용 가능한 외부 자료와 AI 추천이 줄어듭니다. `dist/index.html`을 파일로 직접 여는 방식은 서버 데이터 연결을 사용하지 못합니다.

화면은 `dist/`, 외부 자료 연결은 `server.cjs`와 `lib/`, 계정별 저장 규칙은 `supabase/migrations/`에 있습니다. 이전 결과는 `versions/`에 보존했고, 상세 진행 기록은 상위 실습 폴더의 `작업일지.md`에 있습니다.
