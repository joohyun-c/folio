# folio — 나로부터 시작하는 책 발견

취향을 적고 책을 모으면, 다음 책의 이유가 보이는 **나만의 책장** 웹페이지입니다. 사용자는 관심 주제·읽는 목적·선호 분량·좋아하는 책이나 작가를 선택합니다. 책 카드는 표지를 중심으로 둘러보고, `읽고 싶어요 → 읽는 중 → 다 읽었어요` 보드에 저장할 수 있습니다. 책장은 저장한 책을 주제별로 자동 큐레이션하고, 자주 모은 작가와 현재 읽는 책을 보여줍니다. 한 권을 열면 같은 작가나 주제의 다음 책으로 이어집니다.

기분을 묻는 방식은 중심에서 제외했습니다. Pinterest에서 참고한 점은 **표지 중심의 가변 높이 카드, 빠른 저장, 보드별 정리, 저장한 항목에서 관련 항목으로 이어지는 탐색**입니다. 큰 제목은 영어로, 설명과 조작은 한국어로 구성했습니다. 원본 사이트를 복제하지 않고 folio의 책 탐색 흐름에 맞게 구성했습니다.

## 실행

이 폴더에서 아래 명령을 실행하고 브라우저에서 `http://localhost:8000`을 엽니다.

```sh
python -m http.server 8000 --directory dist
```

설치가 필요 없는 정적 웹페이지입니다. 첫 화면의 관심 주제 하나를 선택하고 **내 추천 새로 보기**를 누르면 추천 순서와 이유가 바뀝니다. 책의 **저장 +**을 눌러 보드에 담아 보세요. 로그인 전 선택과 책장은 이 브라우저에 남습니다. Google 계정 연결 코드는 준비했지만 별도 folio Supabase 프로젝트가 아직 연결되지 않아 실제 로그인과 기기 간 동기화는 현재 사용할 수 없습니다. 책을 찾을 때 관심 주제나 입력한 책·작가 이름은 Google Books 또는 Open Library에 검색어로 전송됩니다.

## Google 계정 연결 계획과 현재 상태

folio에는 **사주 서비스와 분리된 Supabase 프로젝트**를 사용하기로 했습니다. Supabase는 Google 로그인과 계정별 데이터 저장을 맡는 외부 서비스입니다. 로그인 전에는 지금처럼 책을 찾아 브라우저에 저장할 수 있습니다. 로그인 후에는 해당 계정의 책장을 불러오며, 기존 브라우저 책장은 자동 업로드하지 않습니다. 사용자가 **이 브라우저 책장 가져오기**를 선택할 때만 계정 책장과 합칩니다. 로그아웃하면 다시 브라우저 책장으로 돌아옵니다. 계정 저장에 실패하면 실패를 표시하고 재시도할 수 있습니다.

현재 `dist/auth-config.js`의 프로젝트 URL·공개 연결값이 비어 있어 실제 Google 로그인은 연결되지 않았습니다. 새 프로젝트가 준비되면 `supabase/migrations/202610060001_folio_libraries.sql`로 계정별 책장 테이블과 **본인만 읽고 쓰게 제한하는 규칙(RLS)**을 만들고, 해당 프로젝트의 Google 로그인 제공자와 folio 주소의 복귀 URL을 설정해야 합니다. 그 다음 `dist/auth-config.js`에 그 프로젝트의 URL과 **publishable key(브라우저에 공개하도록 설계된 연결값)**만 넣습니다. Google Client Secret이나 Supabase service role 키는 브라우저 파일에 넣지 않습니다. [Google 로그인 설정](https://supabase.com/docs/guides/auth/social-login/auth-google), [복귀 URL 설정](https://supabase.com/docs/guides/auth/redirect-urls), [RLS 안내](https://supabase.com/docs/guides/database/postgres/row-level-security).

연결 후에는 실제 Google 로그인·로그아웃, 계정 A/B의 책장 분리, 다른 브라우저에서 불러오기, 브라우저 책장 가져오기, 저장 실패 재시도를 검증해야 합니다. 원격 저장은 마지막 변경을 기준으로 하므로, 여러 기기에서 동시에 편집한 내용의 자동 병합은 아직 지원하지 않습니다.

**데이터의 한계:** Google Books는 책 정보 공급원이지 추천 판단을 대신하는 서비스가 아닙니다. 2026-10-06 이 작업 환경에서 키 없는 검색은 HTTP 429(사용 한도 오류)였으므로, 이 환경에서는 대체 데이터 경로가 실제로 중요합니다. Google Books가 정상 작동하는 환경에서도 한국어 분류·쪽수·표지가 빠진 책이 있을 수 있습니다. 예시 목록은 실시간 도서 목록이 아닙니다. 판매처 상품 사진은 외부 주소를 참조하므로 바뀌거나 표시되지 않을 수 있습니다. 책과 굿즈의 가격·재고는 folio에 저장하지 않습니다.

## 부록·굿즈 데이터는 어떻게 갱신하나요?

`dist/curiosities.json`이 화면의 상품 목록입니다. 각 항목의 종류(`goods`/`bonus`), 판매처, 제목, 부록 또는 한 줄 소개, 상품 링크, 사진 링크·성격·출처, 마지막 확인일을 담습니다. 이 파일에서 항목을 추가·교체하면 새로고침 후 화면에 반영됩니다. 상단 `updatedAt`은 실제로 상품을 다시 확인한 날짜에만 바꿉니다. 예전 호수의 잡지는 보존된 사례이며 최신호로 표시하지 않습니다. [YES24 일본 무크지·부록 잡지](https://event.yes24.com/bookMagazine?Eventno=110205&CategoryNumber=002), [YES24 독서용품](https://www.yes24.com/Product/Category/Display/006001083), [알라딘 굿즈](https://www.aladin.co.kr/home/wonlymain.aspx)를 새 상품 확인 출발점으로 연결했습니다.

현재는 **편집 목록의 수동 갱신**입니다. [YES24 공식 상품 API](https://developers.yes24.com/api-doc/goods-item-list)의 검색 범위에는 문구/GIFT가 없고, 공개된 응답 필드에 부록 구성·실물 사진이 없습니다. [알라딘 공개 API 안내](https://blog.aladin.co.kr/openapi/popup/6695306)는 검색·상품·목록 API를 설명하지만 부록·굿즈 전체 카탈로그의 자동 동기화는 여기서 확인하지 못했습니다. 따라서 공식 상품 페이지와 사진을 대조한 뒤 목록에 반영하는 방식이 현재는 더 정확합니다. 자동 후보 수집을 붙이더라도 부록 실물·구성·이미지 이용 조건을 확인하는 검수 단계가 필요합니다.
