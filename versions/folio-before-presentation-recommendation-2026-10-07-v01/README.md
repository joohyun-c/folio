# folio — 나로부터 시작하는 책 발견

**folio**는 여러 책을 함께 읽고 있을 때 지금 읽는 책과 다 읽은 책을 한곳에 기록하고, 그 기록에서 자신의 취향을 발견해 다음 책을 고르는 웹페이지입니다. 책을 찾는 경험과 나만의 서가를 함께 만듭니다.

## 기획 의도

여러 책을 오가며 읽다 보면 지금 어떤 책을 읽는지, 왜 골랐는지, 다 읽고 무엇이 남았는지 흐려집니다. 그래서 **읽고 싶은 책·읽는 중인 책·다 읽은 책을 한곳에 모으고**, 완독한 책과 남긴 메모를 다시 볼 수 있는 서가에서 시작했습니다.

앞선 수업의 사주 서비스 실습에서 AI를 이용해 자신을 돌아보는 경험을 만들었습니다. folio에서는 여기에 **실제로 읽고 고른 책의 기록**을 더했습니다. 어떤 책의 문장·인물·주제·실용성을 좋아했는지 남기고, 그 이유가 다음 책의 소개에도 있는지 살펴봅니다. 책을 읽으며 취향을 조금씩 알아가는 것이 목표이지, 몇 권의 기록으로 성격을 판정하려는 것은 아닙니다.

그동안 수업에서 배운 자료 수집·분석, 여러 작업의 분담, AI 연결, 결과 검증, 반복 점검을 한 서비스 흐름에 적용했습니다. **기록 → 취향의 단서 발견 → 근거 있는 다음 책 선택 → 다시 기록**이 folio의 핵심 흐름입니다. 잡지와 함께 오는 소품을 발견하는 기능은 책을 고르는 과정에 더하는 즐거움입니다.

## 현재 구현

관심 주제·읽는 목적·분량을 알려주면 자료로 근거를 확인할 수 있는 후보를 최대 세 권까지 비교합니다. 알라딘의 공개 주간 베스트셀러 목록과 도서관 정보나루·Google Books·Open Library에서 책을 찾고, Gemini는 실제 책 소개를 근거로 한국어 추천 이유를 작성합니다. 검색이 실패하면 편집 예시 책을 보여줍니다. **책 옆의 발견**에서는 잡지와 함께 오는 소품을 사진과 정보로 둘러봅니다.

이제 좋아했던 책 한 권과 **좋았던 이유**를 적으면, 그 이유가 다른 책의 실제 소개에서도 확인될 때 발견 순서와 첫 가판대가 바뀝니다. 맞지 않았던 책과 이유도 선택해 비슷한 후보의 순위를 낮출 수 있습니다. 책 제목만 비슷하거나 ‘베스트셀러’라는 이유만으로 취향 일치라고 표시하지 않습니다. 근거가 없으면 일반 탐색 목록이라고 알려줍니다.

## 실행과 눈으로 확인하기

이 폴더에서 웹 서버를 시작한 뒤 브라우저로 `http://localhost:8768`에 접속합니다. 다른 노트북에서는 `.env.example`을 참고해 비공개 `.env`를 별도로 설정해야 Google Books·Gemini·도서관 정보나루가 연결됩니다. `.env`는 GitHub에 올리지 않습니다. `dist/index.html`을 파일로 직접 열면 자료를 불러오지 못할 수 있습니다.

```sh
node --env-file=.env server.cjs
```

첫 화면에서 상황 예시를 누르거나 **관심 주제·책에서 얻고 싶은 것·읽을 분량**을 직접 고른 뒤 **내 후보 비교하기**를 누릅니다. 읽는 목적은 9가지(새로운 관점, 가볍게 읽기, 실무에 적용, 몰입하는 이야기, 마음 돌보기, 나를 이해하기, 새로운 지식 얻기, 습관 바꾸기, 커리어 방향 찾기)입니다. 주제와 읽는 목적에 연결되는 자료가 있는 책만 상단에 최대 세 권 보여주고, 각 후보의 선택 이유·분량·비교 포인트를 함께 표시합니다. 자료가 부족하면 세 권을 억지로 채우지 않습니다. **이 책으로 시작**을 누르면 바로 **읽는 중** 책장으로 옮겨집니다. 좋아했던 책의 이유는 추가로 맞추고 싶을 때만 펼쳐서 입력합니다. 이유에는 인물·위로·일하는 방식 외에도 문장, 세계관, 유머, 새로운 지식, 자기 성찰, 실천 방법을 고를 수 있습니다. 실제 소개에 같은 단서가 있을 때 추천 순서에 반영합니다. 더 세밀하게 고르고 싶을 때는 **취향 더 자세히 설정하기**를 엽니다. 책 상세에서 추천 이유의 **도움 됐어요/맞지 않아요**를 평가하면 다음 순서에 반영됩니다.

화면은 표지와 한 줄 소개가 먼저 눈에 들어오는 서점 가판대와 인쇄 잡지에서 착안했습니다. 종이색과 흰색을 바탕으로 제목 크기와 장식의 대비를 줄여 책 표지가 중심이 되도록 했습니다. 영어 문구는 화면의 시각적 제목으로만 쓰고, 선택과 동작 설명은 한국어로 유지했습니다.

## 지금 작동하는 기능

- **첫 방문**: 표지와 한 줄 소개가 있는 네 권을 가판대처럼 먼저 보여줍니다. 취향을 정하지 않은 계정에도 아래 편집 목록은 방문·‘다른 책 보기’마다 순서를 바꿉니다. 편집 목록은 실시간 신간으로 표시하지 않습니다.

- **지금 필요한 한 권**: 상황 예시 또는 관심 주제·읽는 목적·분량을 선택하면 근거가 확인된 후보 최대 세 권의 이유·분량·비교 포인트를 표시합니다. 후보를 골라 즉시 ‘읽는 중’으로 옮길 수 있습니다. 자료가 부족하면 0~2권만 표시하고 일반 검색 결과와 구분합니다. 일과 커리어는 세부 관심사 7가지를 고를 수 있습니다.

- **취향 설정**: 관심 주제, 읽고 싶은 분위기, 읽는 이유를 복수 선택합니다. ‘일과 커리어’를 고르면 세부 관심사 7가지가 추가됩니다. 선호 분량·좋아하는 책/작가도 적을 수 있으며 설정은 이 브라우저에 보관됩니다.

- **책에서 시작한 취향**: 좋아한 책과 좋았던 이유를 한 쌍으로 남깁니다. 맞지 않았던 책과 이유는 선택 사항입니다. 책 상세의 ‘취향에 적기’에서 제목을 가져올 수도 있습니다. 실제 책 소개 또는 확인된 분량에서 같은 단서가 보일 때만 추천 순서와 첫 가판대를 바꿉니다. 소설 분위기·인물 선호는 소설로 분류된 후보에, 업무 사례 선호는 관련 업무·경제 분야에만 적용합니다. 취향과 일치하는 후보 수를 보여주며 입력을 지우면 기존 탐색으로 돌아갑니다.

- **개인 추천**: 주제·커리어 세부 관심사·분위기·목적·분량과 저장한 책의 작가를 비교해 책 순서를 정합니다. 책 소개의 명시적 단서가 있는 책만 상단에 올립니다. Gemini 키를 연결하면 실제 검색된 후보에서만 최대 세 권을 고르고, 책 소개에 실제로 있는 문장을 근거로 한국어 이유를 작성합니다. 근거를 검증할 수 없으면 AI 추천을 버립니다. 제목의 ‘실무’ 같은 단어와 짧은 쪽수는 단독 근거가 아닙니다. 도움 됐어요/맞지 않아요 평가는 다음 순서에 반영하며 취소할 수 있습니다.

- **책 찾기**: 소설 등 주요 주제는 알라딘의 공개 주간 베스트셀러 목록과 Google Books·Open Library를 함께 봅니다. `소설` 검색에는 한국·일본·영미·추리·판타지·SF·로맨스 분야를 고르는 버튼을 제공합니다. `이번 주 베스트`, `최근 2년 출간`, `한국어 책`, `소개 있는 책`, `300쪽 이하`로 좁힐 수 있습니다. 소설은 최근 2년 출간 목록을 기본으로 보여주며 오래된 책은 `전체`에서 볼 수 있습니다. 판매 순위와 출간일은 서로 다른 정보로 표시합니다.

- **개인 책장**
  - 읽고 싶어요·읽는 중·다 읽었어요로 구분하고, 한 줄 메모와 주제별 서가·통계를 제공합니다.
  - 책과 부록을 직접 이름 붙인 취향 보드에 함께 담을 수 있습니다.
  - 읽고 싶은 책 중 최대 세 권의 순서를 정하고 분량·메모를 비교한 뒤 ‘지금 읽기’로 옮길 수 있습니다.
  - 완독한 책의 주제에 따라 서재 색과 질감이 바뀝니다. 여러 권 중 분위기 기준이 될 책을 고르고, 아직 읽는 책의 완독 후 모습도 미리 볼 수 있습니다.
  - 입체 서가는 저장 권수에 따라 늘어나며 한 쪽에 최대 12권을 표시합니다. 13권부터 다음 서가로 넘기고, 표지를 누르면 책 상세가 열립니다.
  - 단계별 필터, 최근 완독 네 권의 날짜·메모, 가장 많이 읽은 주제, 전체 목록의 제목·작가 검색과 정렬을 제공합니다. 장식과 벽지는 접힌 설정에서 조정합니다.
  - **확인:** 시험용 13권을 담아 서가 2쪽·전체 13권·완독 필터·읽은 기록을 브라우저에서 확인했습니다.

- **이어서 탐색**: 책 상세에서 같은 작가의 책만 연결하고, 설명이 없는 책은 정보가 부족하다고 표시합니다.

- **책 옆의 발견**
  - 출처를 확인한 잡지 소품 18개를 큰 사진과 소품명 중심으로 보여줍니다.
  - 종류별 개수, 소품·브랜드 검색, 발행 호·이름순 정렬, 저장한 소품만 보기를 제공합니다.
  - ‘소품 저장’ 한 번으로 ‘갖고 싶은 소품’ 보드에 담고, 취향 보드에도 따로 담을 수 있습니다.
  - 잡지 호·사진 출처·목록 확인일을 표시하고 [宝島社 최신 부록 목록](https://tkj.jp/goods/furoku/)으로 연결합니다. 재고·가격은 실시간 정보가 아닙니다.

## 국내 도서 검색 연결 상태

현재 [알라딘 분야별 주간 베스트셀러](https://www.aladin.co.kr/shop/common/wbest.aspx?BestType=Bestseller&BranchType=1&CID=50917)의 공개 목록을 서버가 읽어 순위·표지·출간 월을 보여줍니다. 목록은 6시간 캐시하고, 일시적 장애에는 7일 이내 마지막 성공 목록만 `오래된 자료`로 반환합니다. 책 소개는 해당 책의 공개 상품 페이지에서 상위 3권만 가져와 Gemini 추천의 근거로 사용하며 24시간 캐시합니다. **2026-10-07 실제 소설 주간 순위 30권과 상위 세 권의 소개를 확인했고, `소설` 검색 화면에서 최근 2년 출간 17권과 해당 책 두 권의 Gemini 한국어 추천 이유를 확인했습니다.** 이 목록은 알라딘의 주간 판매 순위이며, 모든 책이 최근 출간작이라는 뜻은 아닙니다. 공개 페이지 구조가 바뀌면 목록을 불러오지 못할 수 있습니다. Google Books는 folio 전용 Books API 키를 서버에만 두고 한국어 검색에 사용합니다. `데이터 분석` 검색에서 한국어 책 20권, 소개 12권, 표지 18권을 확인했습니다. Google Books 자체에는 판매 순위가 없으므로 결과를 베스트셀러로 표시하지 않습니다. [도서관 정보나루](https://data4library.kr/apiUtilization)의 `srchBooks`와 `srchDtlList` 서버 코드도 준비했습니다. **2026-10-07 실제 정보나루 검색 응답을 확인했습니다.** 다만 넓은 검색어에는 관련성이 낮은 책도 섞이므로, 추천 상단은 책 소개와 선택 조건을 다시 대조합니다. 카카오 코드는 이전 작업물로 남아 있지만 현재 화면에서는 호출하지 않습니다.

공개된 [과거 데이터 안내 자료](https://www.dataedu.kr/etc/files/%EC%A0%9C%EC%9D%B4%EC%97%90%EC%8A%A4%EB%8D%B0%EC%9D%B4%ED%83%80_%EC%98%A4%ED%94%88DB.pdf)는 도서관 정보나루를 무료로 분류합니다. [현재 공식 API 안내](https://www.data4library.kr/apiUtilization)에는 요금 문구 없이 회원가입 → 인증키 신청 → 발급 절차가 실려 있습니다. 따라서 공개 자료로는 **무료 제공 근거를 확인했지만 현재 개별 계정의 최종 이용 조건까지 확정할 수는 없습니다.** 인증키는 이미 비공개 `.env`에 저장했고 `node --env-file=.env server.cjs`로 서버를 실행했습니다. `.env`는 Git에서 제외됩니다. 이미 8765 화면을 별도 웹 서버로 열고 있다면 예시처럼 `PORT=8768`을 두어 검색 서버를 함께 실행할 수 있습니다. 이 실습 환경에서는 기존 8767 서버가 이전 코드로 실행 중이어서 folio 화면은 8768을 먼저 확인합니다. 인증키가 비활성 상태이거나 일시 오류일 때에는 화면에 연결 상태를 표시합니다. 인증키는 브라우저 파일에 넣지 않습니다.

Gemini는 [Google AI Studio의 API 키](https://ai.google.dev/gemini-api/docs/api-key)를 서버의 `GEMINI_API_KEY`로 받습니다. [공식 가격표](https://ai.google.dev/gemini-api/docs/pricing)에 무료 등급이 있지만 모델별 호출 한도가 있습니다. 실제 책의 ID·제목·저자·공개 소개와 선택한 취향, 좋아하거나 맞지 않았던 책 제목·이유를 보내며 책장 메모는 보내지 않습니다. AI가 반환한 책 ID와 소개 인용문을 서버가 원본 후보와 대조하고, 불일치하면 표시하지 않습니다. **`gemini-3.5-flash-lite`로 실제 한국어 추천 응답과 원문 인용 검증을 확인했습니다.**

**추가 데이터원 선택 기준:** 회원가입과 무료 인증키 발급까지 허용합니다. 도서관 정보나루 인증키를 연결해 국내 검색을 보강했고 Google Books와 Open Library를 함께 사용합니다. 알라딘 OpenAPI는 이용 URL 등록이 필요하고, 카카오는 사용자가 앱 생성을 보류해 현재 화면에서 호출하지 않습니다.

Goodreads는 책장·추천·리뷰의 **기능 비교 대상**이며 도서 데이터 공급원으로 사용하지 않습니다.

## Google 계정 연결 상태

사용자가 선택한 대로 사주 서비스와 분리된 **folio 전용 Supabase 프로젝트**와 Google Cloud OAuth 클라이언트를 만들었습니다. `folio_libraries` 테이블에 본인 계정만 읽고 쓸 수 있는 접근 제한을 적용하고, Google 제공자와 복귀 주소를 설정했습니다. 로그인·계정별 책장·브라우저 책장 가져오기 코드는 `dist/auth.js`에 연결돼 있습니다. **별도 localhost 화면에서 실제 Google 로그인과 계정 책장 불러오기를 확인했습니다.** Google OAuth는 현재 테스트 상태이며 다른 기기 복원·계정 A/B 분리는 아직 검증하지 않았습니다.

연결 상태와 마지막 확인 항목은 다음과 같습니다.

1. folio 전용 Supabase 프로젝트, Google 로그인 제공자·복귀 주소, `folio_libraries` 접근 제한: 설정 완료.
2. `dist/auth-config.js`에 프로젝트 URL과 공개 연결값인 publishable key: 반영 완료. Google Client Secret이나 service role 키는 브라우저 파일에 넣지 않았습니다.
3. 실제 로그인과 계정 책장 불러오기: 브라우저 확인 완료. 로그아웃, 브라우저 책장 가져오기, 다른 브라우저에서 복원, 계정 A/B 분리: 검증 대기.

참고: [Supabase Google 로그인](https://supabase.com/docs/guides/auth/social-login/auth-google), [복귀 주소 설정](https://supabase.com/docs/guides/auth/redirect-urls), [계정별 접근 제한](https://supabase.com/docs/guides/database/postgres/row-level-security).

- 로그인 전 취향과 메모는 브라우저 저장소에 남습니다.
- 책 검색어는 연결된 Google Books·Open Library·도서관 정보나루에 전송됩니다.
- Gemini에는 취향 선택, 좋아하거나 맞지 않았던 책의 제목·이유, 후보 책의 공개 소개를 보냅니다. 책장 메모는 보내지 않습니다.

## 추천 이유 평가

[첫 추천 이유 평가표](eval/recommendation-eval-2026-10-06-v01.md)와 [두 번째 평가](eval/recommendation-eval-2026-10-06-v02.md)에 서로 다른 취향 입력 6개와 실패 사례를 기록했습니다. 두 번째 평가에서는 상위 18권 중 11권에 소개가 있었지만 목적 표현이 있는 사례가 0/6이었습니다. [이번 목적별 재평가](eval/recommendation-eval-2026-10-06-v03.md)에서는 목적별 검색과 검색 응답의 책 소개 활용, 상단 후보 제한을 적용했습니다. 같은 6개 입력 중 **2개 사례에서** 책 소개의 목적 관련 표현이 있는 책이 상단에 나타났고, 나머지 4개는 조건에 맞는 후보가 없어 상단을 비웠습니다. 제목이나 쪽수만으로 적합하다고 주장하지 않습니다. 소개의 홍보 문구는 실제 독자 만족도를 입증하지 않으며, 이는 개발자의 기능 평가입니다.

## 책 옆의 발견 데이터 갱신

`dist/curiosities.json`은 사람이 원문을 확인해 넣은 **편집 목록**입니다. 2026-10-06에 [宝島社 최신 부록 목록](https://tkj.jp/goods/furoku/)과 각 잡지·증간의 공식 페이지에서 11개를 추가로 확인해 전체 18개가 되었습니다. 기존 [リンネル 11월호 증간의 mofusand 파우치](https://tkj.jp/book/?cd=TD081161&mag=) 등과 알라딘의 [MonoMax](https://www.aladin.co.kr/shop/wproduct.aspx?ItemId=391846745)·[リンネル](https://www.aladin.co.kr/shop/wproduct.aspx?ItemId=391010778) 판매 페이지도 유지합니다. 사진은 부록 이미지 중심이며 잡지 표지와 구별해 표시합니다.

항목에는 부록 종류(`category`), 발행 호(`issue`), 브랜드(`brand`), 구성, 상품/발행사 주소, 사진 주소·출처, 확인 날짜가 있습니다. 발행 호는 정렬에, 브랜드와 구성은 검색에, 종류는 필터와 개수 표시에 사용합니다. 화면에는 목록 확인일을 표시하고 45일 이상 지나면 새 호 확인이 필요하다고 알립니다. 오래된 호는 발견 자료로 남기며 구매 가능하다고 주장하지 않습니다. **실시간 재고·가격·자동 수집 기능은 없습니다.**

Codex 앱에 **매월 1일 `folio 잡지 소품 월간 갱신` 작업**을 설정했습니다. 이 작업은 [宝島社 최신 부록 목록](https://tkj.jp/goods/furoku/)과 공식 상품 페이지에서 새 호·사진·브랜드를 확인한 뒤 기존 ID를 보존하며 파일을 갱신하도록 요청합니다. 출처를 확인하지 못한 항목은 넣지 않습니다. 이는 웹사이트가 실시간으로 외부 목록을 불러오는 기능이 아니며, 공개 사이트에 반영하려면 변경 파일의 배포가 별도로 필요합니다. 사용자가 제시한 [알라딘 부록 종류별 모음전](https://www.aladin.co.kr/events/wevent.aspx?EventId=309111)과 [YES24 일본 무크지·부록 기획전](https://event.yes24.com/bookMagazine?Eventno=110205&CategoryNumber=002)을 화면에 연결했습니다. 공개 배포 전에는 외부 이미지 사용 조건과 주소 안정성을 확인해야 합니다.

## 완료 기준과 남은 일

### 구현하고 확인한 것

- **책 발견·추천**: 상황·주제·읽는 목적·분량으로 근거가 있는 후보를 최대 세 권 비교하고, 고른 책을 ‘읽는 중’으로 옮깁니다. 실제 화면에서 한국어 후보와 이동을 확인했습니다. 좋아한 책의 이유·맞지 않았던 이유, 추천 이유 평가도 순서에 반영합니다. 근거가 부족하면 상단 후보를 채우지 않습니다.
- **도서 데이터**: 알라딘 주간 순위, Google Books, Open Library, 도서관 정보나루를 연결했습니다. 실제 한국어 검색 응답과 표지·소개를 확인했으며, 자료가 없는 책에는 부족하다고 표시합니다. Gemini는 실제 후보의 소개와 인용문을 확인한 뒤 한국어 이유를 표시합니다.
- **개인 책장**: 읽기 단계·메모·취향 보드·다음에 읽을 세 권·주제별 서재를 구현했습니다. 13권을 저장해 첫 서가 12권과 다음 서가 1권, 완독 필터·읽은 기록·390px 화면 배치를 확인했습니다. 이번 점검에서는 시험 보드에 책을 담고 빼기, 다음 독서 목록에 책을 넣고 빼기를 확인한 뒤 시험 변경을 되돌렸습니다.
- **책 옆의 발견**: 출처를 확인한 소품 18개의 사진, 검색·정렬·저장·보드 필터·확인일을 구현했습니다. 저장 후 새로고침 유지까지 화면에서 확인했습니다. 매월 새 호를 점검하는 Codex 작업을 설정했습니다.
- **Google 로그인**: folio 전용 프로젝트와 계정별 접근 제한을 설정하고, 실제 로그인·계정 책장 불러오기를 확인했습니다.
- **이번 점검**: ‘일과 커리어’를 고르면 세부 항목 7개가 나타나고, 상위 선택을 해제했다가 다시 고르면 세부 선택이 초기화되는 것을 별도 로컬 화면에서 확인했습니다. 서버·추천 연동 자동 시험 26개가 모두 통과했습니다.

### 아직 확인이 필요한 것

- **실제 이용자 판단**: 책 소개에 맞는 표현이 있어도 독자가 책을 좋아할지는 알 수 없습니다. 서로 다른 취향의 이용자가 추천 이유와 후보를 직접 평가해야 합니다. [추천 이유 평가 기록](eval/recommendation-eval-2026-10-06-v03.md)에는 여섯 입력 중 두 사례만 목적 관련 소개가 있는 후보로 연결됐고, 네 사례는 근거 부족으로 비워 둔 결과가 있습니다.
- **계정 간 복원**: 다른 기기에서의 복원과 서로 다른 두 계정의 데이터 분리는 실제 계정·기기에서 최종 확인해야 합니다. 현재 확인한 범위는 한 계정의 로그인과 책장 불러오기입니다.
- **정기 갱신·공개 배포**: 매월 갱신 작업의 첫 실행과 변경 내용의 공개 사이트 반영은 일정이 도래하거나 배포할 때 확인해야 합니다. 외부 사진의 사용 조건·주소 안정성도 공개 전 확인이 필요합니다.
- **추가 사용성 점검**: 많은 책을 저장했을 때의 속도, 과거 저장 데이터 이전, 키보드 조작, 넓은 화면 배치는 아직 화면으로 재검증하지 않았습니다.

Google Books의 키 없는 호출은 이 작업 환경에서 HTTP 429(호출 한도 오류)를 보였으나, 현재는 Books API 전용 키를 연결했습니다. 외부 책 정보에는 분류·쪽수·표지가 없을 수 있고, 분위기 판정은 제목·설명·분류의 단어를 이용한 **가벼운 추정**입니다. 책 내용을 읽고 판단한 결과가 아닙니다.
