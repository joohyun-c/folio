# folio — 나로부터 시작하는 책 발견

**folio**는 내 취향을 입력하고 책을 발견해 나만의 책장에 모으는 웹페이지입니다. 책 정보는 Google Books를 우선 사용하고, 연결이 안 되면 Open Library나 편집한 예시 책을 보여줍니다. 잡지 화면에서는 일본 잡지의 실제 부록 사진을 중심으로 둘러봅니다.

## 실행과 눈으로 확인하기

이 폴더에서 웹 서버를 시작한 뒤 브라우저로 `http://localhost:8000`에 접속합니다. `dist/index.html`을 파일로 직접 열면 `curiosities.json`을 불러오지 못할 수 있습니다.

```sh
python -m http.server 8000 --directory dist
```

첫 화면에서 **오늘 끌리는 분위기**를 하나 골라 **내 추천 새로 보기**를 눌러보세요. 후보와 추천 이유가 바뀝니다. **일본 잡지 부록** 메뉴에서는 실물 사진을 보고 가방·파우치·생활 소품별로 좁힐 수 있습니다. 책을 저장한 뒤 **내 책장**에서 보드와 주제별 서가를 확인할 수 있습니다.

## Google 계정 연결 상태

**실제 Google 로그인은 아직 작동하지 않습니다.** 사용자가 선택한 대로 사주 서비스와 분리된 folio 전용 Supabase 프로젝트를 사용할 계획입니다. 로그인·계정별 책장·브라우저 책장 가져오기 코드는 `dist/auth.js`에 준비했지만, 새 프로젝트 생성과 연결 설정은 끝나지 않았습니다. 따라서 현재는 작동하지 않는 로그인 버튼을 숨기고 이 브라우저의 책장을 사용합니다. 다른 기기와 동기화된다고 표시하지 않습니다.

연결에 필요한 일은 다음 순서입니다.

1. folio 전용 Supabase 프로젝트를 만듭니다.
2. Google 로그인 제공자와 이 웹페이지의 복귀 주소를 설정합니다.
3. `supabase/migrations/202610060001_folio_libraries.sql`을 적용해 계정별 책장과 본인만 읽고 쓰는 제한 규칙을 만듭니다.
4. `dist/auth-config.js`에 프로젝트 URL과 공개 연결값인 publishable key를 넣습니다. Google Client Secret이나 service role 키는 브라우저 파일에 넣지 않습니다.
5. 실제 로그인·로그아웃, 브라우저 책장 가져오기, 다른 브라우저에서 복원, 계정 A/B 분리를 검증합니다.

참고: [Supabase Google 로그인](https://supabase.com/docs/guides/auth/social-login/auth-google), [복귀 주소 설정](https://supabase.com/docs/guides/auth/redirect-urls), [계정별 접근 제한](https://supabase.com/docs/guides/database/postgres/row-level-security). 로그인 전 취향과 메모는 브라우저 저장소에 남습니다. 책을 찾을 때 주제·분위기나 입력한 책/작가 이름은 Google Books 또는 Open Library에 검색어로 전송됩니다.

## 일본 잡지 부록 데이터 갱신

`dist/curiosities.json`은 사람이 원문을 확인해 넣은 **편집 목록**입니다. 2026-10-06에 [宝島社의 リンネル](https://tkj.jp/liniere/202611/), [otona MUSE](https://tkj.jp/otonamuse/202611/), [InRed](https://tkj.jp/inred/202610/), [MonoMax](https://tkj.jp/max/202610/) 공식 호수와 부록을 확인했고, 알라딘의 [MonoMax](https://www.aladin.co.kr/shop/wproduct.aspx?ItemId=391846745)·[リンネル](https://www.aladin.co.kr/shop/wproduct.aspx?ItemId=391010778) 판매 페이지도 연결했습니다. 여섯 사진은 부록 사진이며 잡지 표지와 구별해 표시합니다.

항목에는 부록 종류(`category`), 발행 호, 구성, 상품/발행사 주소, 사진 주소·출처, 확인 날짜가 있습니다. 새 호를 확인한 뒤 이 파일에 추가하면 화면에 반영됩니다. **실시간 재고·가격·자동 수집 기능은 없습니다.** 오래된 7월호는 발행 호가 보이도록 남겼으며 현재 구매 가능하다고 주장하지 않습니다. 더 찾아볼 곳으로 사용자가 제시한 [YES24 일본 무크지·부록 기획전](https://event.yes24.com/bookMagazine?Eventno=110205&CategoryNumber=002)도 화면에 연결했습니다. 공개 배포 전에는 외부 이미지 사용 조건과 주소 안정성을 확인해야 합니다.

## 완료 기준과 남은 일

| 업무 | 통과 기준 | 상태 |
| --- | --- | --- |
| 취향 입력 | 주제·분위기·목적·분량을 선택하고 새로고침 뒤 유지 | 구현, 분위기 화면 검증 |
| 추천 | 다른 분위기를 고르면 후보/순위와 실제 일치한 추천 이유가 바뀜 | 구현, 자동·브라우저 시나리오 추가 검증 필요 |
| 책 정보 | Google 성공 응답과 실패 시 Open Library/예시 전환 | 실패 전환 검증, Google 성공 재검증 필요 |
| 책장 | 저장·이동·삭제·메모 유지 및 주제별 서가 | 이전 검증 완료, 오래된 저장 데이터 이전 재검증 필요 |
| 일본 잡지 부록 | 출처가 확인된 실물 사진 6종과 종류별 필터 표시 | 구현·브라우저 사진 6장 로딩/필터 검증 완료 |
| 상품 갱신 | 새 호를 확인해 목록·확인일 수정 | 수동 운영 가능, 자동화 없음 |
| Google 로그인 | 전용 프로젝트에서 실로그인·계정별 복원/격리 | 코드 준비, 프로젝트 미연결·실검증 없음 |
| 공개 준비 | 이미지 사용 조건 확인, 모바일·키보드 조작 검증 | 진행 전 |

Google Books의 키 없는 호출은 이 작업 환경에서 HTTP 429(호출 한도 오류)를 보였습니다. 외부 책 정보에는 분류·쪽수·표지가 없을 수 있고, 분위기 판정은 제목·설명·분류의 단어를 이용한 **가벼운 추정**입니다. 책 내용을 읽고 판단한 결과가 아닙니다.

## 파일과 보존본

`dist/index.html`은 화면, `dist/styles.css`는 디자인, `dist/app.js`는 책·추천·책장 동작, `dist/curiosities.json`은 부록 목록입니다. `dist/auth.js`와 `dist/auth-config.js`는 계정 연결 코드와 공개 설정입니다. `supabase/migrations/`에는 계정별 책장 데이터베이스 규칙이 있습니다. 수정 전 파일은 `versions/folio-before-japanese-bonus-2026-10-06-v01/`에 보존했습니다. 세부 작업 기록은 상위 폴더의 `작업일지.md`에 있습니다.
