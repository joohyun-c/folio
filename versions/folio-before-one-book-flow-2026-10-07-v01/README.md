# folio — 나로부터 시작하는 책 발견

**folio**는 내 취향을 입력하고 책을 발견해 나만의 책장에 모으는 웹페이지입니다. 알라딘의 공개 주간 베스트셀러 목록으로 최근 읽히는 한국어 책을 먼저 찾고, Google Books와 Open Library로 검색 범위를 넓힙니다. Gemini는 실제 책 소개를 근거로 한국어 추천 이유를 작성합니다. 검색이 실패하면 편집 예시 책을 보여줍니다. **책 옆의 발견**에서는 잡지와 함께 오는 소품을 사진과 정보로 둘러봅니다.

이제 좋아했던 책 한 권과 **좋았던 이유**를 적으면, 그 이유가 다른 책의 실제 소개에서도 확인될 때 발견 순서와 첫 가판대가 바뀝니다. 맞지 않았던 책과 이유도 선택해 비슷한 후보의 순위를 낮출 수 있습니다. 책 제목만 비슷하거나 ‘베스트셀러’라는 이유만으로 취향 일치라고 표시하지 않습니다. 근거가 없으면 일반 탐색 목록이라고 알려줍니다.

## 실행과 눈으로 확인하기

이 폴더에서 웹 서버를 시작한 뒤 브라우저로 `http://localhost:8768`에 접속합니다. 다른 노트북에서는 `.env.example`을 참고해 비공개 `.env`를 별도로 설정해야 Google Books·Gemini·도서관 정보나루가 연결됩니다. `.env`는 GitHub에 올리지 않습니다. `dist/index.html`을 파일로 직접 열면 자료를 불러오지 못할 수 있습니다.

```sh
node --env-file=.env server.cjs
```

첫 화면에서 **관심 주제·읽는 이유·분량**을 고르고 **책 찾아보기**를 누르면, 주제와 읽는 이유에 연결되는 자료가 있는 책만 상단에 최대 세 권 보여줍니다. 조건을 만족하는 책이 없으면 상단을 억지로 채우지 않고 일반 탐색 목록만 남깁니다. 추천 카드에서 책 소개의 표현 또는 확인 가능한 정보를 보고 **도움 됐어요/맞지 않아요**를 눌러 다음 순서에 반영할 수 있습니다. 더 세밀하게 고르고 싶을 때만 **취향 더 자세히 설정하기**를 엽니다. 책 상세에서 **내 취향 보드에 담기**를 할 수 있고, **책 옆의 발견**에서 잡지 소품도 같은 보드에 담을 수 있습니다. **내 책장**의 다음 3권은 분량·내 메모를 비교하고 **지금 읽기**로 읽는 중으로 옮길 수 있습니다.

화면은 표지와 한 줄 소개가 먼저 눈에 들어오는 서점 가판대와 인쇄 잡지에서 착안했습니다. 종이색과 흰색을 바탕으로 제목 크기와 장식의 대비를 줄여 책 표지가 중심이 되도록 했습니다. 영어 문구는 화면의 시각적 제목으로만 쓰고, 선택과 동작 설명은 한국어로 유지했습니다.

## 국내 도서 검색 연결 상태

현재 [알라딘 분야별 주간 베스트셀러](https://www.aladin.co.kr/shop/common/wbest.aspx?BestType=Bestseller&BranchType=1&CID=50917)의 공개 목록을 서버가 읽어 순위·표지·출간 월을 보여줍니다. 목록은 6시간 캐시하고, 일시적 장애에는 7일 이내 마지막 성공 목록만 `오래된 자료`로 반환합니다. 책 소개는 해당 책의 공개 상품 페이지에서 상위 3권만 가져와 Gemini 추천의 근거로 사용하며 24시간 캐시합니다. **2026-10-07 실제 소설 주간 순위 30권과 상위 세 권의 소개를 확인했고, `소설` 검색 화면에서 최근 2년 출간 17권과 해당 책 두 권의 Gemini 한국어 추천 이유를 확인했습니다.** 이 목록은 알라딘의 주간 판매 순위이며, 모든 책이 최근 출간작이라는 뜻은 아닙니다. 공개 페이지 구조가 바뀌면 목록을 불러오지 못할 수 있습니다. Google Books는 folio 전용 Books API 키를 서버에만 두고 한국어 검색에 사용합니다. `데이터 분석` 검색에서 한국어 책 20권, 소개 12권, 표지 18권을 확인했습니다. Google Books 자체에는 판매 순위가 없으므로 결과를 베스트셀러로 표시하지 않습니다. [도서관 정보나루](https://data4library.kr/apiUtilization)의 `srchBooks`와 `srchDtlList` 서버 코드도 준비했습니다. **정보나루 인증키는 비공개 설정에 있으나 계정이 승인 대기 중이고 실제 호출은 `API 활성화 상태가아닙니다.`를 반환했습니다.** 카카오 코드는 이전 작업물로 남아 있지만 현재 화면에서는 호출하지 않습니다.

공개된 [과거 데이터 안내 자료](https://www.dataedu.kr/etc/files/%EC%A0%9C%EC%9D%B4%EC%97%90%EC%8A%A4%EB%8D%B0%EC%9D%B4%ED%83%80_%EC%98%A4%ED%94%88DB.pdf)는 도서관 정보나루를 무료로 분류합니다. [현재 공식 API 안내](https://www.data4library.kr/apiUtilization)에는 요금 문구 없이 회원가입 → 인증키 신청 → 발급 절차가 실려 있습니다. 따라서 공개 자료로는 **무료 제공 근거를 확인했지만 현재 개별 계정의 최종 이용 조건까지 확정할 수는 없습니다.** 인증키는 이미 비공개 `.env`에 저장했고 `node --env-file=.env server.cjs`로 서버를 실행했습니다. `.env`는 Git에서 제외됩니다. 이미 8765 화면을 별도 웹 서버로 열고 있다면 예시처럼 `PORT=8768`을 두어 검색 서버를 함께 실행할 수 있습니다. 이 실습 환경에서는 기존 8767 서버가 이전 코드로 실행 중이어서 folio 화면은 8768을 먼저 확인합니다. 승인 대기 중에는 화면의 검색 결과에 `국내 도서 인증키 승인 대기 중`이 표시됩니다. 인증키는 브라우저 파일에 넣지 않습니다.

Gemini는 [Google AI Studio의 API 키](https://ai.google.dev/gemini-api/docs/api-key)를 서버의 `GEMINI_API_KEY`로 받습니다. [공식 가격표](https://ai.google.dev/gemini-api/docs/pricing)에 무료 등급이 있지만 모델별 호출 한도가 있습니다. 실제 책의 ID·제목·저자·공개 소개와 선택한 취향, 좋아하거나 맞지 않았던 책 제목·이유를 보내며 책장 메모는 보내지 않습니다. AI가 반환한 책 ID와 소개 인용문을 서버가 원본 후보와 대조하고, 불일치하면 표시하지 않습니다. **`gemini-3.5-flash-lite`로 실제 한국어 추천 응답과 원문 인용 검증을 확인했습니다.**

| [Google Books](https://developers.google.com/books/docs/v1/using) | 한국어 제한 검색과 표지·소개 보완 | folio 프로젝트에서 Books API만 허용한 키를 비공개로 연결했고 실데이터·웹 화면을 검증함. 다른 노트북에는 `.env`를 별도로 설정해야 함 |

**네이버 책 검색은 후보에서 제외했습니다.** [네이버의 공식 종료 공지](https://developers.naver.com/notice/article/32530)에 따르면 이 API는 2026년 7월 31일 종료됐고 NAVER API HUB에도 대체 API가 없습니다. 기존 검색 API 설명서는 남아 있지만 현재 이용 가능하다는 뜻이 아닙니다. 사용자가 카카오 앱 생성을 보류했으므로 카카오 앱은 만들지 않았습니다.

**추가 데이터원 선택 기준:** 회원가입과 무료 인증키 발급까지 허용합니다. 도서관 정보나루가 승인되면 국내 검색을 우선하고 Google Books와 Open Library를 함께 보여줍니다. 알라딘은 이용 URL 등록이 필요하고, 카카오는 사용자가 앱 생성을 보류해 현재 화면에서 호출하지 않습니다.

Goodreads는 책장·추천·리뷰의 **기능 비교 대상**이며 도서 데이터 공급원으로 사용하지 않습니다.

## Google 계정 연결 상태

사용자가 선택한 대로 사주 서비스와 분리된 **folio 전용 Supabase 프로젝트**와 Google Cloud OAuth 클라이언트를 만들었습니다. `folio_libraries` 테이블에 본인 계정만 읽고 쓸 수 있는 접근 제한을 적용하고, Google 제공자와 복귀 주소를 설정했습니다. 로그인·계정별 책장·브라우저 책장 가져오기 코드는 `dist/auth.js`에 연결돼 있습니다. **별도 localhost 화면에서 실제 Google 로그인과 계정 책장 불러오기를 확인했습니다.** Google OAuth는 현재 테스트 상태이며 다른 기기 복원·계정 A/B 분리는 아직 검증하지 않았습니다.

연결 상태와 마지막 확인 항목은 다음과 같습니다.

1. folio 전용 Supabase 프로젝트, Google 로그인 제공자·복귀 주소, `folio_libraries` 접근 제한: 설정 완료.
2. `dist/auth-config.js`에 프로젝트 URL과 공개 연결값인 publishable key: 반영 완료. Google Client Secret이나 service role 키는 브라우저 파일에 넣지 않았습니다.
3. 실제 로그인과 계정 책장 불러오기: 브라우저 확인 완료. 로그아웃, 브라우저 책장 가져오기, 다른 브라우저에서 복원, 계정 A/B 분리: 검증 대기.

참고: [Supabase Google 로그인](https://supabase.com/docs/guides/auth/social-login/auth-google), [복귀 주소 설정](https://supabase.com/docs/guides/auth/redirect-urls), [계정별 접근 제한](https://supabase.com/docs/guides/database/postgres/row-level-security). 로그인 전 취향과 메모는 브라우저 저장소에 남습니다. 책을 찾을 때 검색어는 Google Books·Open Library에 전송되고, 정보나루 승인 후에는 그곳에도 전송됩니다. Gemini에는 취향 선택과 후보 책의 공개 소개만 전송되며 개인 메모는 전송되지 않습니다.

## 추천 이유 평가

[첫 추천 이유 평가표](eval/recommendation-eval-2026-10-06-v01.md)와 [두 번째 평가](eval/recommendation-eval-2026-10-06-v02.md)에 서로 다른 취향 입력 6개와 실패 사례를 기록했습니다. 두 번째 평가에서는 상위 18권 중 11권에 소개가 있었지만 목적 표현이 있는 사례가 0/6이었습니다. [이번 목적별 재평가](eval/recommendation-eval-2026-10-06-v03.md)에서는 목적별 검색과 검색 응답의 책 소개 활용, 상단 후보 제한을 적용했습니다. 같은 6개 입력 중 **2개 사례에서** 책 소개의 목적 관련 표현이 있는 책이 상단에 나타났고, 나머지 4개는 조건에 맞는 후보가 없어 상단을 비웠습니다. 제목이나 쪽수만으로 적합하다고 주장하지 않습니다. 소개의 홍보 문구는 실제 독자 만족도를 입증하지 않으며, 이는 개발자의 기능 평가입니다.

## 책 옆의 발견 데이터 갱신

`dist/curiosities.json`은 사람이 원문을 확인해 넣은 **편집 목록**입니다. 2026-10-06에 [宝島社 최신 부록 목록](https://tkj.jp/goods/furoku/)과 각 잡지·증간의 공식 페이지에서 11개를 추가로 확인해 전체 18개가 되었습니다. 기존 [リンネル 11월호 증간의 mofusand 파우치](https://tkj.jp/book/?cd=TD081161&mag=) 등과 알라딘의 [MonoMax](https://www.aladin.co.kr/shop/wproduct.aspx?ItemId=391846745)·[リンネル](https://www.aladin.co.kr/shop/wproduct.aspx?ItemId=391010778) 판매 페이지도 유지합니다. 사진은 부록 이미지 중심이며 잡지 표지와 구별해 표시합니다.

항목에는 부록 종류(`category`), 발행 호(`issue`), 브랜드(`brand`), 구성, 상품/발행사 주소, 사진 주소·출처, 확인 날짜가 있습니다. 발행 호는 정렬에, 브랜드와 구성은 검색에, 종류는 필터와 개수 표시에 사용합니다. 화면에는 목록 확인일을 표시하고 45일 이상 지나면 새 호 확인이 필요하다고 알립니다. 오래된 호는 발견 자료로 남기며 구매 가능하다고 주장하지 않습니다. **실시간 재고·가격·자동 수집 기능은 없습니다.**

Codex 앱에 **매월 1일 `folio 잡지 소품 월간 갱신` 작업**을 설정했습니다. 이 작업은 [宝島社 최신 부록 목록](https://tkj.jp/goods/furoku/)과 공식 상품 페이지에서 새 호·사진·브랜드를 확인한 뒤 기존 ID를 보존하며 파일을 갱신하도록 요청합니다. 출처를 확인하지 못한 항목은 넣지 않습니다. 이는 웹사이트가 실시간으로 외부 목록을 불러오는 기능이 아니며, 공개 사이트에 반영하려면 변경 파일의 배포가 별도로 필요합니다. 사용자가 제시한 [알라딘 부록 종류별 모음전](https://www.aladin.co.kr/events/wevent.aspx?EventId=309111)과 [YES24 일본 무크지·부록 기획전](https://event.yes24.com/bookMagazine?Eventno=110205&CategoryNumber=002)을 화면에 연결했습니다. 공개 배포 전에는 외부 이미지 사용 조건과 주소 안정성을 확인해야 합니다.

## 파일과 보존본

`dist/index.html`은 화면, `dist/styles.css`는 디자인, `dist/app.js`는 책·추천·책장 동작, `dist/taste.js`는 책에서 시작한 취향의 근거 검사, `dist/curiosities.json`은 부록 목록입니다. `server.cjs`는 Google Books·도서관 정보나루·Gemini를 서버에서 호출하며, `.env.example`은 비공개 키 설정 예시입니다. `lib/data4library.cjs`와 `lib/gemini-recommend.cjs`에 각 연동과 검증 규칙을 둡니다. `dist/auth.js`와 `dist/auth-config.js`는 계정 연결 코드와 공개 설정입니다. `supabase/migrations/`에는 계정별 책장 데이터베이스 규칙이 있습니다. 이번 개인화 변경 전 파일은 `versions/folio-before-taste-books-2026-10-07-v01/`에 보존했습니다. 세부 작업 기록은 상위 폴더의 `작업일지.md`에 있습니다.
